# ADR-0006: 04시 Actions 배치와 공개 개발·비공개 운영 경계

- 기록일: 2026-11-08
- 결정 상태: **Accepted — 실행 방식·격리 경계만**
- 구현/배포/가동 상태: **미구현·미가동**. 기존 개발 CI의 오프라인 브라우저 검증과 운영 배치를 구분한다.
- 연결 이슈: [#11](https://github.com/silverThunder09/hermes-job-automation/issues/11)
- 이전 제안: [ADR-0003](0003-scheduled-collection-and-retention.md)의 실행 호스트·시각 부분만 이 결정으로 구체화한다. 보존/삭제 등 나머지 제안은 Proposed다.

## 사용자 확인과 승인 범위

사용자는 상시 NAS/서버 없이 GitHub 예약 작업으로 매일 새벽 4시에 실행하는 방향을 확인했다. 이어 공개 개발 CI와 인증·개인자료를 사용하는 운영 작업의 분리 설계를 확정하도록 요청했다. 이 기록은 아래 실행 방식과 격리 경계의 결정이며, 아직 선택하지 않은 인증 기술이나 운영 권한까지 소급 승인하지 않는다.

## 결정

1. **GitHub-hosted runner의 일회성 배치**를 운영 실행 방식으로 선택한다. 형님의 PC와 로컬 Hermes가 꺼져 있어도 실행할 수 있는 구조를 목표로 하며 별도 상시 Hermes Cloud/VPS/Gateway를 필수 조건으로 두지 않는다. 에이전트가 필요하면 해당 작업 안에서만 실행한다.
2. 목표 일정은 **매일 04:00, `Asia/Seoul`**이다. 정확한 시작/완료 시각은 보장하지 않는다. 실제 예약 등록은 수동 원격 실행과 승인 관문을 통과한 뒤 별도로 한다.
3. 현재 공개 소스 저장소와 **비밀 없는 개발 CI는 공개로 유지**한다. 구독 인증·채용 계정 세션·개인 서류를 사용하는 운영 작업은 **별도 비공개 운영 영역**으로 분리한다. 운영 전용 비공개 저장소가 후보이며 실제 이름·생성·권한은 후속 결정/승인 대상이다. 이 문서로 저장소를 생성하거나 현재 공개 범위를 바꾸지 않는다.
4. 임시 runner 디스크를 영속 저장소로 취급하지 않는다. 앱 상태의 공유 원본은 [ADR-0005](0005-supabase-postgres-only.md)의 Supabase PostgreSQL 결정을 유지한다. 개인 파일·인증의 구체적 보관/갱신 방식은 아래 미결정 관문에서 분리한다.
5. 기존 GPT 계정/구독 활용을 우선 검토하고 신규 유료 API나 유료 fallback을 임의 도입하지 않는다. 원격 모델 클라이언트와 인증 방식, 실제 구독 한도·사용량 합산은 아직 검증하지 않았다. 이번 결정은 인증 성공이나 항상 무료라는 보장이 아니다.

## 공개·비공개 경계

```text
공개 소스 저장소
  └─ 코드·문서·합성 fixture 기반 개발 CI (운영 인증/개인자료 없음)

비공개 운영 영역 — 아직 생성·구현·가동하지 않음
  └─ 검토한 코드 버전의 일회성 작업
       ├─ 필요한 브라우저·에이전트 실행
       ├─ 허용된 공고/회사 조사·문서 작업·정책 판단
       ├─ 상태/결과의 승인된 영속 저장소 저장·재조회
       └─ 작업 종료·runner 폐기
```

비공개 저장소도 인증 파일·개인 서류를 Git에 커밋하는 장소는 아니다. 운영 구현에서는 검토된 정확한 코드 버전과 허용된 실행 입력만 사용하도록 설계/검증해야 한다. 신뢰하지 않는 PR/fork 코드나 임의 revision에 인증을 제공하지 않는다. 이 조건은 구현 합격 기준이지 현재 배포된 통제의 증거가 아니다.

## 일정 표현과 신뢰성

다음은 **문서 예시**이며 `.github/workflows/`에 등록한 활성 workflow가 아니다.

```yaml
on:
  schedule:
    - cron: '0 4 * * *'
      timezone: Asia/Seoul
```

GitHub 공식 문서는 timezone을 생략하면 UTC가 기본이며 IANA 시간대 지정도 지원한다고 설명한다. 예약 실행은 기본 브랜치의 최신 workflow를 사용한다. 특히 정각의 부하로 지연되거나 대기 작업이 누락될 수 있으므로 04시 예약을 정시 실행 보장으로 표현하지 않는다. 공개 저장소의 예약은 저장소 활동이 60일 없으면 자동 비활성화될 수 있다. 선택한 비공개 운영 영역의 정책도 실제 가동 전에 확인한다. 누락 감지·중복 방지·checkpoint·재개 기준은 구현 시 검증한다.

## 아직 Proposed인 항목과 실행 전 관문

| 관문 | 다음 결정/구현 범위 | 통과 증거와 별도 승인 |
|---|---|---|
| 운영 대상·권한 | 비공개 운영 저장소/영역의 실제 이름, 접근자, 신뢰 코드 전달 방식 | 비공개 상태·권한·코드 버전 확인. 새 저장소 생성/권한 설정은 별도 승인 |
| 모델 실행 | Hermes 자체 모델 경로 또는 standalone Codex CLI 등 실제 클라이언트 | 원격에서 비개인 합성 요청 성공. 현재 대화의 Hermes 로그인을 자동 이전하지 않음 |
| 인증 보관·갱신 | secure restore→클라이언트 자체 갱신→안전한 write-back·직렬화 | 인증 실패·저장 실패·동시 실행·만료의 안전 중단 검증. 저장소/Secret writer 권한·만료를 먼저 선택. 등록/로그인은 별도 승인 |
| 자료·결과 | 개인 원본/초안/최종본/증빙의 저장·조회·모델 전송·보존 정책 | 자료·수신처·접근·보관 범위 승인 후 최소 자료만 취급. 기존 DB 결정은 개인 파일 업로드/삭제 승인이 아님 |
| 비용·한도 | 계정의 포함량·예산·초과 중단·timeout | 실제 계정의 차단 설정과 작업 사용량 확인. 새 과금/크레딧 구매/유료 fallback 없음. 한도 소진 시 중단/재개 계약은 구현·검증 전 |
| 사이트·가동 | 플랫폼별 허용 범위, 수동 전체 실행, 예약/제출 권한 | [사람인 관문](../SARAMIN_ACCESS.md) 확인과 비제출 경로 검증 후 각각 승인. 예약 승인으로 실제 제출을 허용하지 않음 |

위 후보 중 **GitHub Secrets 저장과 fine-grained PAT/App writer 중 무엇을 쓸지도 미결정**이다. OpenAI의 Codex 관리 인증 CI 안내는 신뢰하는 비공개 자동화용이며 공개/오픈소스 저장소에 해당 workflow를 쓰지 말라고 명시한다. 또한 그 안내는 Codex 외 generic OAuth 클라이언트에 적용되지 않는다. Hermes 자체 OAuth와 동일한 것으로 취급하지 않는다. 인증 bundle을 매번 오래된 초기 Secret로 복사하는 것만으로 장기 갱신이 검증되지는 않는다.

인증 관문의 후속 비교안은 [ADR-0007](0007-remote-model-auth.md)과 [상세 수명주기 계약](../REMOTE_AUTH_DESIGN.md#credential-lifecycle)에 기록한다. **Proposed이며 기술 선택·운영 생성/가동은 미승인**이다. 이 문서의 실행/격리 결정과 나머지 관문의 상태를 바꾸지 않는다.

## 대안·비용·되돌리는 조건

- Windows 작업 스케줄러: 로컬 PC-off 요구를 충족하지 못하므로 선택하지 않는다. 기존 로컬 예시는 선택적 수동 경로로 남긴다.
- 상시 Cloud/VPS: 지속 서비스에는 유용하지만 현재 사용자의 상시 서버 없음·배치 요구에 불필요한 운영 책임을 더하므로 필수로 도입하지 않는다.
- 공개 저장소에서 민감 운영까지 실행: 개발 CI 무료 이점만으로 구독 인증 지침·개인자료 경계를 무시할 수 없으므로 선택하지 않는다.
- 공개 개발 + 비공개 일회성 운영: 선택한 방향이다. 별도 상시 서버는 없지만 비공개 runner 실행량·영속 저장소·모델 한도는 각각 검증해야 한다.

공개 표준 runner의 무료 실행과 비공개 운영의 계정별 포함량/초과 과금은 구분한다. Actions artifact 보관량은 runner 작업 디스크와 다르며 개인자료 영속 보관 설계를 대신하지 않는다. 모델 구독이 Actions·Storage 비용을 포함한다고 가정하지 않는다.

원격 인증을 안전하게 유지할 수 없거나 사이트가 필요한 자동화를 허용하지 않거나 비용 차단/실행 한도를 충족하지 못하면 운영 활성화를 보류한다. 대안은 별도 Proposed ADR로 비교하며 자동으로 유료 API/VPS로 전환하지 않는다. 사용자 PC·원본 DB/자료는 보존한다.

## 이번 변경의 완료 기준

- 실행 방식·시간대·공개/비공개 경계의 결정 문서와 관련 안내/라우팅을 일관되게 연결한다.
- 로컬 문서 링크·회귀, 독립 두 축 리뷰, 해당 head/base 개발 CI를 확인한다. 이 성공은 운영 배치/인증/MVP 완료가 아니다.
- 실제 저장소 생성, Secrets·로그인·모델 호출·개인자료·운영 DB·사이트 접근/제출·예약·삭제·과금 설정은 하지 않는다.
