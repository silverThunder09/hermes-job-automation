# ADR-0004: 커밋 품질 게이트·이슈 대응·승인 경계 — 제안

- 기록일: 2026-11-07
- 결정 상태: Proposed — 사용자의 결정 확인 전
- 구현/설치/운영 상태: 정책 문서 초안만 작성. 훅 실행 파일·installer·Git 설정·원격 보호는 미구현/미적용
- 연결 이슈/PR: 정책 초안 문서의 PR 게시 승인됨. PR 본문에서 추적하며 정책 확정·훅 구현/설치 승인과는 별개
- 상세 정책: [WORKFLOW_POLICY](../WORKFLOW_POLICY.md)

## 배경과 확인 사실

사용자는 커밋 훅, 이슈 발견 시 처리, 사람이 승인해야 하는 경우까지 명확히 하도록 요청했습니다. 기존 규칙은 이슈→ADR→PR 흐름과 일반 승인 원칙에 머물렀습니다. 현재 저장소는 Python 기반이고 Node package.json은 없으며, 확인한 Git 기본 hook 디렉터리에는 `.sample` 파일만 있습니다. 훅 설치가 완료됐다는 근거는 없습니다.

기존 스킬의 Husky/lint-staged 권장안을 Python 저장소에 그대로 적용하면 별도 Node 의존성과 설정이 생깁니다. 도구부터 설치하지 않고 대안을 비교합니다.

## 대안

| 대안 | 장점 | 단점/관리 비용 |
|---|---|---|
| Git 기본 훅 + 기존 Python | 추가 언어/패키지 없이 시작, 기존 환경과 맞음 | 설치/해제·부분 staging·push snapshot·Windows/worktree 호환성을 직접 검증해야 함 |
| Python pre-commit 프레임워크 | 여러 검사 도구의 버전/환경/캐시 관리 지원 | 새 개발 의존성, 최초 다운로드/네트워크, 도구별 버전·Python 호환 관리 |
| Husky + lint-staged | JS 생태계에서 익숙한 staged 검사와 도구 통합 | 이 프로젝트에는 Node/package 설정 추가 필요, Python 검사 환경도 별도 관리 |
| 로컬 훅 없이 CI만 사용 | 설치 단계가 단순 | 실수 검출이 늦음. 개인정보/키가 push된 후에는 차단이 늦을 수 있음 |

## 제안

Git 기본 훅 + 기존 Python으로 `pre-commit`, `commit-msg`, `pre-push`를 구현하고 CI/리뷰를 함께 사용합니다. 신뢰할 수 있는 staged 내용과 정확한 push 대상 커밋을 검사하며 원격 DB 쓰기나 개인 자료 전송을 하지 않습니다. 검사 자동 수정/자동 stage는 하지 않습니다.

심각도별 이슈 대응과 사람 승인 범위는 상세 정책에 따르되, 그 문서의 새 프로젝트 정책도 현재는 검토 초안입니다. 기존 비밀 보호와 외부 변경 승인 경계는 계속 유효합니다.

## 승인·검증·되돌리기

사용자의 결정 확인 → 실제 임시 Git 저장소에서 성공/차단 시나리오 검증 → 설치 범위/기존 hook 보존·worktree 영향 확인 → 별도 활성화 승인 순으로 진행합니다. 로컬 설치와 GitHub CI/원격 branch protection은 각각 다른 적용 단계입니다.

추가 도구가 필요하거나 staged/push snapshot 처리 비용이 커지면 Python pre-commit 방식 등을 다시 비교합니다. 기존 `core.hooksPath`/hook은 덮어쓰지 않으며 해제/복구 방법을 검증합니다. 네트워크·과금·원격 변경은 이 ADR 제안으로 승인된 것이 아닙니다.
