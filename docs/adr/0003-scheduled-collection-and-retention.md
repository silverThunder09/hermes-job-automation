# ADR-0003: 새벽 예약 수집과 임시 파일 보존 — 제안

- 기록일: 2026-11-07
- 결정 상태: Proposed — 보존·삭제·운영 세부 제안은 미결정
- 구현/배포 상태: 미구현·미가동. 기존 GitHub Actions는 테스트 CI임
- 연결: 세부 실행 범위/시간/예산/삭제 대상 확정 전의 로컬 설계 초안

후속 결정: 실행 호스트·시각·공개/비공개 격리 경계는 [ADR-0006](0006-actions-batch-boundary.md)에서 별도로 확정했습니다. 아래의 초기 대안·미결정 목록은 제안 이력으로 보존하며, 시간대/호스트 항목은 후속 결정을 우선합니다. 보존·삭제·인증·운영 가동을 일괄 승인하거나 이 ADR 전체를 Accepted로 바꾼 것은 아닙니다.

## 배경과 방향

사용자는 로컬에서 개발하면서 PC가 꺼진 새벽에도 공고를 수집하기를 원합니다. GitHub Actions 같은 단기 예약 실행기와 Supabase 공유 상태를 조합하고, 임시 파일은 5일 보관 후 정리하는 방향에 공감했습니다. 이 기록은 구체적인 예약 가동/파일 삭제/비용 발생까지 승인된 것으로 취급하지 않습니다.

## 대안

- Windows 작업 스케줄러: PC가 꺼져 있으면 실행되지 않습니다.
- 상시 서버/Hermes Gateway: 지속 실행이 필요한 경우 유리하지만 서버 운영과 비용을 관리해야 합니다.
- GitHub Actions 예약 배치: 간헐적 작업에 맞지만 정확한 정각 시작/무중단 실행은 보장하지 않으며 실행량·비용·브라우저/OCR 호환성 검증이 필요합니다.

## 구현 전 확정할 사항

- 실행 시간/시간대, 대상 사이트와 허용 접근 범위, 로그인/CAPTCHA 중단 정책.
- 공고별 저장, 전체 timeout, 부분 실패·중복 실행·재시도 정책.
- 계정의 무료 포함량/예산/초과 중단 설정과 실제 작업 소요량.
- Windows OCR의 Linux 대체 경로와 실제 공고 검증.
- 5일 정리 대상(임시 캡처/OCR/초안), 원본·최종 제출본·접수 증빙의 예외, 만료 기준 시각과 정리 주기.
- 파일 삭제는 Storage API로 수행하고 DB 메타데이터만 지워 실제 파일을 남기지 않도록 검증. 5일 보관만으로 용량/전송량 한도가 보장되지는 않음.

결정 확인, 코드·테스트, 실제 수동 실행 검증, 별도 예약/삭제 승인과 원격 가동 확인을 거친 뒤 상태를 갱신합니다. 현재는 설계 초안이며 예약 workflow나 cleanup이 만들어졌다고 보고하지 않습니다.
