# ADR-0012: 명시적 허가 미확인에 따른 일괄 수집 중지 조건 제거

- 기록일: 2026-11-16
- 결정 상태: **Accepted — 사용자의 명시적 정책 변경·문서 병합 지시**
- 연결 이슈: [#31](https://github.com/silverThunder09/hermes-job-automation/issues/31)
- 대체 범위: ADR-0006·ADR-0011 및 기존 접근 문서의 **명시적 허가 미확인만으로 중단**하는 조건만 대체한다. 실행 호스트·수집/저장 격리·비용·개인정보·제출 승인·보존 결정은 유지한다.
- 구현 상태: 정책 문서와 오프라인 문서 계약만 변경. **운영 코드 변경 없음**, 수집기·예약 활성화나 실제 DB 저장 성공을 뜻하지 않는다.

## 배경과 사용자 결정

명시된 제한, 허용 근거 미확인, 기술적 실패, 미구현을 모두 수집 불가로 설명해 작업이 멈췄다. 사용자는 “사이트가 허용한다고 명시한 근거가 없으면 실행하지 않는다”는 규칙을 제거하고 문서를 수정·병합하라고 명시적으로 결정했다. 이 기록은 그 결정의 범위를 남기며 다른 사이트의 약관을 변경하거나 법적 허가를 부여하지 않는다.

## 결정과 판정 소유자

현행 판정의 단일 원본은 [플랫폼 접근 정책](../PLATFORM_ACCESS.md)이다. **명시적 허가 미확인만으로 중단하지 않는다.** 미확인만으로 금지나 허용을 확정하지 않고, 적용되는 명시적 제한과 접근 상태를 구분해 사용자 승인 범위의 공개·비로그인 공고를 소량·유한하게 처리한다. 소스별 API 존재·자격 증명·구현 상태는 별도로 보고한다.

공식 문의나 별도 허가서 확보를 모든 공개 페이지 읽기의 필수 선행 조건으로 만들지 않는다. 관련 작업에 실제 적용되는 수집·복제 금지나 사전 동의 요건이 확인되면 해당 작업은 중단한다. robots의 대상 경로 제한과 운영자 고지도 확인하며, 허용 지시를 데이터 재이용의 포괄 허가로 바꾸지 않는다. CAPTCHA·로그인·OTP·접근 차단은 우회하지 않는다.

## 유지하는 승인·격리 경계

- [ADR-0011](0011-private-collection-writer.md)의 **최대 10개 공고·유한한 1회** 검증 범위를 늘리지 않는다. 새 사이트·추가 횟수·대량 복제·예약은 기존 사용자 승인 범위를 따로 대조한다.
- 공개 공고의 최소 필요 항목과 출처·시각·불명확한 조건을 기록하고, agent 조사 결과를 `user_reviewed_manual`로 위장하지 않는다. 개인정보·개인 이력서·비공개 자료로 확장하지 않는다.
- collection/storage job 분리, 검토한 코드 고정, 브라우저에 DB 키를 주지 않는 원칙, 기존 상태·메모 보존, 정확한 재조회·중복 검증을 유지한다.
- 유료 서비스·카드·과금 변경, 운영 SQL·권한 변경, 실제 지원·업로드·삭제·예약 가동·모델 인증 이전은 **별도 승인**이다. 이 문서 병합은 그러한 실행을 새로 승인하거나 가동하지 않는다.
- 사람인 공식 API 폐기는 유지한다. 기존 collector의 `manual_only`/`approval_required`나 플래그, 점핏 전용 writer 검증 코드를 이 문서 변경으로 바꾸지 않는다.

## 대안·위험·비용

일괄 허가 확인을 유지하는 대안은 불확실성을 줄이지만 단순한 근거 미발견을 기술적 금지로 취급하고 공개 소량 작업까지 정지시키는 문제가 있다. 모든 제한을 무시하는 대안은 선택하지 않는다. 대신 해당 제한의 근거·적용 대상과 공개 접근 상태를 기록하는 방식을 선택했다.

허가 문구가 없더라도 저작권·데이터베이스 권리·별도 운영정책의 불확실성은 남는다. 이를 허용 확정으로 보고하지 않고 최소 항목·승인된 건수·낮은 요청 빈도로 범위를 제한한다. 새로운 의존성·인프라·과금 자원은 추가하지 않는다. 공개 연구 근거에 개인 계정 사용량·인증정보를 섞지 않는다.

## 검증·되돌리는 조건

문서 계약은 허가 미확인만 있는 경우와 명시적 제한·접근 차단을 구분하고, 관련 진입점·과거 기록이 현행 원본으로 연결되는지 검사한다. 문서 테스트 성공은 브라우저 수집·Supabase 저장·예약 성공의 증거가 아니다.

운영상 새 제한·접근 차단·데이터 손상·예상치 못한 비용이 확인되면 관련 작업을 중단하고 사실과 영향을 기록한다. 정책을 다시 바꾸려면 후속 결정과 검토된 문서 변경으로 처리하며 원본 데이터·기존 작업을 삭제하거나 과거 공식 인용을 소급 수정하지 않는다.
