# 에이전트 주도 PR 자동화

## 자동화의 범위

이 프로젝트의 첫 PR 자동화는 **명시적으로 게시 권한을 받은 에이전트가 기존 Git/GitHub CLI로 검증·리뷰·커밋·push·PR 생성/갱신·CI 확인을 수행하는 흐름**입니다. 새 API 키, 상시 PR 봇, 새 write 권한 workflow 또는 자동 병합을 도입하지 않습니다.

현재 준비된 자동 CI는 기존 테스트와 `PR policy / metadata`입니다. 이 문서만으로 push 이벤트 기반 PR 생성 봇이나 무인 AI 리뷰 서비스가 설치되는 것은 아닙니다. 에이전트가 실행 중이 아니면 이 게시 흐름은 자동으로 시작되지 않습니다.

## 입력과 승인

- 대상 저장소·base/head 브랜치·변경 범위·실제 연결 이슈 또는 초기 bootstrap 예외.
- 변경/검증/ADR/외부 영향이 채워진 PR 본문과 Conventional Commits 제목.
- 사용자에게 받은 커밋·push·PR 발행·리뷰/수정의 승인 범위.
- 병합, branch protection, 자동 병합, force-push, 저장소 공개 범위 변경, Secrets 등록, 유료 실행은 별도 승인입니다. 이미 승인한 같은 범위의 수정/검증/게시를 반복해서 묻지 않습니다.

## 실행 절차

1. 저장소 규칙과 기존 작업 트리·remote·현재 공개 범위를 확인합니다. 다른 작업은 별도 worktree로 보존합니다. `gh auth status`로 기존 인증을 확인하되 토큰을 추출/출력하지 않습니다.
2. `git fetch` 후 base SHA와 PR 중복을 조회합니다. 동일 head/base의 PR이 있으면 새로 만들지 않고 기존 PR을 사용합니다. 이슈 실재 여부와 bootstrap 적용 가능성은 리뷰에서 확인합니다.
3. **커밋 전 로컬 리뷰**: 실제 변경과 새 파일을 읽고 개인정보/비밀/DB/생성 문서가 섞이지 않았는지 검사합니다. 관련/회귀 테스트, 문서 링크/YAML, PR 메타데이터 검사를 실행합니다. 실패하면 승인된 범위 안에서 수정하고 재검증합니다.
4. 승인 범위의 파일만 명시적으로 stage합니다. staged diff와 경로를 재확인하고 규칙에 맞는 메시지로 커밋합니다. 모든 미추적 파일을 일괄 추가하지 않습니다. 검증 실패를 무시하거나 훅을 우회하지 않습니다.
5. 해당 작업 브랜치만 push하고 원격 head SHA를 다시 읽어 로컬 commit과 비교합니다. PR은 브랜치 commit이 있어야 생성되므로 커밋 전에 PR을 만들 수 있다고 안내하지 않습니다.
6. `gh pr create` 또는 기존 PR 갱신으로 게시하고 PR URL·head/base·본문·변경 파일을 재조회합니다. 성공 응답만으로 완료 처리하지 않습니다.
7. **PR 리뷰**: 최신 head/base를 기준으로 보안/표준과 요구사항/정확성을 검토합니다. AI 결과는 AI 검토임을 밝히고, 같은 계정 작성자의 자기 승인을 시도하지 않습니다. `COMMENT` 리뷰를 사용하며 사람의 최종 승인으로 표현하지 않습니다.
8. 차단 결함이 발견되면 그 범위만 수정 → 회귀 검사 → 추가 커밋/push → 최신 SHA 재검토를 수행합니다. 동일한 근거 없는 수정을 반복하지 않고 최대 2회의 수정·재검증으로 해결하지 못하면 결과와 블로커를 보고합니다. PR/이슈를 임의로 닫지 않습니다.
9. `gh pr checks` 또는 해당 head SHA의 실제 Actions 결과를 읽어 테스트/정책 검사가 끝났는지 확인합니다. 대기/실패를 성공으로 표현하지 않습니다. base/head가 바뀌면 영향을 받는 검증·리뷰를 갱신합니다.
10. PR URL, 정확한 commit, 로컬/원격 검사 결과, 리뷰·남은 결함, 미병합 여부를 보고합니다. 병합 승인이 없으면 열린 PR로 종료합니다.

## 유지할 경계

- PR 형식 검사는 실제 이슈 존재·ADR 승인·테스트 결과의 진실성을 보증하지 않습니다.
- 사람 승인 정책과 hook 설치 제안(ADR-0004)을 이 자동화 문서로 자동 확정하지 않습니다.
- 명령에는 본문/제목을 셸 코드로 삽입하지 않고 안전한 인자/파일 입력을 사용합니다. 인증정보나 개인 지원 자료는 body 파일에도 넣지 않습니다.
- CI workflow가 게시되어 실행되는 것과 branch protection이 필수 검사로 강제하는 것은 다릅니다.
- 향후 push 트리거 PR 봇·호스팅 AI 리뷰가 필요하면 실행 호스트·권한·인증·비용·중복/재시도·기존 정책과의 상호작용을 ADR로 먼저 결정합니다.
