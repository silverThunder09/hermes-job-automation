# 개발 컨벤션

## 브랜치·이슈·커밋

- 새 브랜치: `feat/<issue>-short-description`, `fix/...`, `refactor/...`, `docs/...`, `test/...`, `ci/...`, `chore/...`.
- 실제 이슈 번호를 사용합니다. 로컬 초안에는 임시 설명 이름을 쓸 수 있으나 게시 전 연결을 확정합니다. 기존 브랜치는 승인 없이 이름을 바꾸지 않습니다.
- 커밋과 PR 제목: `type(scope): 설명`. scope는 소문자 영역명으로 선택 사항이며 설명은 한국어/영어 모두 가능합니다. 제목은 100자 이하입니다.
- type: `feat`, `fix`, `docs`, `refactor`, `test`, `ci`, `chore`, `perf`, `build`, `style`, `revert`. 호환성 파괴는 `!`와 본문 migration 설명을 사용합니다.
- 한 커밋은 한 논리적 변경입니다. 포맷 전체 변경과 기능 변경을 섞지 않습니다. 이슈 번호 예시는 형식 설명일 뿐 실제 존재를 보증하지 않습니다.
- 커밋·push·PR/이슈 게시·병합은 사용자가 승인한 범위 안에서만 수행합니다.

## Python·구조

- Python 3.9+ 호환, 개발/CI 대상은 3.11입니다. 새 문법·의존성의 최소 버전을 확인합니다.
- 들여쓰기 4칸, 모듈/함수/변수 `snake_case`, 클래스 `PascalCase`, 상수 `UPPER_SNAKE_CASE`.
- 공개 메서드와 I/O 결과에 타입·오류 계약을 드러냅니다. CLI는 인자/출력/종료 코드, 모듈은 도메인 규칙과 저장/외부 연동을 맡습니다.
- 상태 DB는 ADR-0005에 따라 Supabase PostgreSQL 단일 backend로 통일합니다. 초기화/설정 검증은 공통 factory에 모으고 원격 연결 실패를 로컬 DB 성공으로 조용히 대체하지 않습니다. 이전 SQLite 파일은 보관물이지 앱/테스트 backend가 아닙니다.
- 의존성은 `pyproject.toml`에 호환 범위와 함께 선언합니다. 새 프레임워크/서비스/주요 라이브러리는 먼저 ADR로 대안을 비교합니다. 의존성 추가만으로 실제 사용·배포되었다고 표현하지 않습니다.

## 데이터·오류·보안

- 공고 ID·URL·명령 원문을 보존하고 정규화된 비교용 값은 구분합니다. OCR 결과는 원본 확인 전 검증된 사실로 취급하지 않습니다.
- DB 시각은 timezone-aware UTC, 사용자 표시는 명시한 시간대를 사용합니다.
- 수집 갱신이 지원 상태·메모·증빙을 덮어쓰지 않게 합니다. 중복/동시성은 서버 제약과 트랜잭션으로 검증합니다.
- `.env`·키·OAuth 토큰·원본/생성 지원 서류·프로필·실행 DB는 커밋하지 않습니다. 샘플/테스트에는 합성 fixture 또는 최소 공개 정보만 씁니다.
- 예외 메시지에 인증 헤더·API 응답 원문·네트워크 예외 원문을 그대로 노출하지 않습니다. 불확실한 쓰기는 재조회로 조정하고 무조건 재시도하지 않습니다.
- 외부 변경은 승인 범위·정확한 대상·실행 결과·재조회 결과를 남깁니다. 개인정보 증빙은 비공개 로컬 기록에 두고 PR에는 비밀 없는 요약만 적습니다.

## 테스트·완료 기준

- 테스트명은 사용자가 관찰할 행동을 설명합니다. 내부 호출 순서보다 저장/조회 결과와 실패 계약을 검증합니다.
- 수정 범위 테스트와 전체 회귀 테스트를 실행합니다. 원격 자격 증명 없이 테스트할 수 있게 하고, 실제 DB 테스트는 명시적 opt-in으로 격리합니다.
- 문서만 바뀌어도 링크·템플릿·검사 스크립트가 실제로 동작하는지 확인합니다.
- formatter/linter를 도입했다면 설정과 CI를 함께 추가합니다. 아직 설치하지 않은 도구를 필수 검사로 통과했다고 주장하지 않습니다.
- 구현 완료, 로컬 테스트 완료, 원격 적용 완료, 사용자 승인 완료를 각각 구분합니다.
